\chapter{Completion Queues and Non-Lossy Results}
\label{chap:completion-queues}

A completion queue (CQ) carries asynchronous kernel-operation results to
userspace. Its central safety rule is that a full userspace ring must not silently
discard a terminal result.

\section{When to use a completion queue}

Use submission/completion when the operation belongs to the \textbf{kernel or a
hardware-facing mechanism}, not to another userspace service:

\begin{itemize}
    \item Timer expiry.
    \item DMA completion (disk read finished, packet transmitted).
    \item IRQ-derived device completion (data available on UART).
    \item Asynchronous page operations.
    \item Waiting for thread or process exit.
    \item Kernel-managed asynchronous object work.
\end{itemize}

Use endpoint IPC (\autoref{chap:endpoints}) when one protection domain invokes another.
Confusing these two paths leads to architectural mistakes: a service call is not a
kernel operation, and a reply token is not a completion record.

\section{The CQ ring: a shared-memory completion buffer}

A completion queue is a \textbf{shared-memory ring buffer} between the kernel
(producer) and userspace (consumer). A single 4 KiB page contains a header and a
circular array of fixed-size entries.

Each entry is 32 bytes:

\begin{lstlisting}[style=rustCode]
struct CompletionEntry {
    operation: u64,    // operation identifier (e.g., timer id)
    cookie: u64,       // opaque value set by the submitter
    status: u32,       // completion status code
    flags: u32,        // per-entry flags
    result: i64,       // operation result (e.g., bytes read)
}
\end{lstlisting}

The ring page is mapped read-write in userspace because the consumer advances its
tail; the kernel accesses the same frame through its privileged mapping. The ABI
assigns each side its own fields:

\begin{itemize}
    \item Userspace drains entries without syscalls: advancing the
        consumer tail is a store to a shared page; reading entries is a load.
        No kernel crossing needed for the common fast path.
    \item The kernel publishes entries with a release fence: the consumer
        sees coherent data without additional synchronization.
    \item Overflow is detected, not hidden: an overflow counter in the
        header lets userspace detect when entries were produced faster than
        consumed.
\end{itemize}

\section{The non-lossy invariant}

\begin{quote}
\textbf{A terminal operation result must never be silently lost because the
userspace CQ ring is full.}
\end{quote}

This is an architectural invariant, so when the ring is full, the
kernel has several options:

\begin{itemize}
    \item Retain overflow in a per-domain kernel backlog: entries that
        cannot fit in the ring wait in a kernel-side buffer. When userspace
        drains the ring, the backlog drains into it.
    \item Stop accepting new submissions: the kernel may return
        \texttt{WouldBlock} on \texttt{submit}, applying backpressure at the
        submission point rather than at the completion point.
    \item Propagate \texttt{WouldBlock}: the CQ's wait operation can
        indicate that the ring is full and must be drained.
\end{itemize}

The overflow counter is pressure telemetry: it tells the consumer that it is
falling behind.

In a critical system, a lost completion for a disk write or a timer
expiry is a correctness bug with potentially severe consequences. CharlotteOS
treats each completion as a datum that must be delivered at least once.

\section{Per-shard CQ partitioning}

Each address space owns a set of completion queues, keyed by \rustfn{CqId}. Queue
0 is the default. For a service with multiple sitas shards, \textbf{per-shard CQ
rings} enable targeted wakes:

\begin{itemize}
    \item Shard A's executor waits on CQ 0.
    \item Shard B's executor waits on CQ 1.
    \item A completion destined for Shard A is posted to CQ 0.
    \item Only Shard A's executor is woken; Shard B is undisturbed.
\end{itemize}

This prevents cross-shard completion stealing (a pathological behavior where one
busy shard drains entries intended for another) and keeps wakeup latency
proportional to the number of entries, not the number of shards.

\section{Operation lifecycle}

Every asynchronous operation transitions through a defined state machine:

\begin{center}

    state/.style={draw, rounded corners, align=center, inner sep=4pt, font=\small},

    \node[state, right=0.45cm of accepted] (inflight) {InFlight};
    \node[state, right=0.45cm of inflight] (completed) {Completed};
    \node[state, right=0.45cm of completed] (observed) {Result\\Observed};
    \node[state, right=0.45cm of observed] (reclaimed) {Resources\\Reclaimed};

    \node[state, below=0.4cm of submitted] (rejected) {Rejected};
    \node[state, below=0.4cm of inflight] (failed) {Failed};
    \node[state, below=0.4cm of completed] (cancelled) {Cancelled};

    \draw[->] (created) -- (submitted);
    \draw[->] (submitted) -- (accepted);
    \draw[->] (accepted) -- (inflight);
    \draw[->] (inflight) -- (completed);
    \draw[->] (completed) -- (observed);
    \draw[->] (observed) -- (reclaimed);

    \draw[->] (submitted) -- (rejected);
    \draw[->] (inflight) -- (failed);
    \draw[->] (inflight) -- (cancelled);
\end{tikzpicture}
\end{center}

Each transition is explicit and observable:

\begin{description}
    \item[Created] The operation descriptor exists in userspace but has not been
        submitted to the kernel.
    \item[Submitted] \texttt{submit()} has been called. The kernel has the
        operation record but has not yet validated it.
    \item[Accepted / Rejected] The kernel has validated the operation. It may be
        rejected immediately (invalid parameters, insufficient rights, queue
        full) with a synchronous error.
    \item[InFlight] The operation is being processed. The kernel or device owns
        any associated buffers.
    \item[Completed / Failed / Cancelled] A terminal state. The result is posted
        to the CQ. Buffer ownership returns to userspace.
    \item[ResultObserved] The consumer has read the CQ entry.
    \item[ResourcesReclaimed] The operation's capability-table slot has been
        freed (via \texttt{close}).
\end{description}

\section{Checked waiting on a CQ}

When a shard's executor has no ready tasks, it calls \texttt{checked CQ wait} on its
assigned queue. The kernel blocks the calling thread until one of three things
happens:

\begin{enumerate}
    \item A completion entry is posted to the CQ.
    \item An explicit \texttt{CQ\_WAKE} arrives (from another shard or the
        kernel).
    \item A deadline elapses (timeout variant: a finite checked wait).
\end{enumerate}

The current syscall is 88, with timeout milliseconds, queue ID and an explicit
finite/event-only flag. The safe runtime returns readiness or deadline expiry,
or a distinct admission/invalid-request error. Syscalls 12/42 and their ignored
entry-count threshold are retired. Rejection cannot advance a protocol clock or
end a pending borrow; the caller retains the original operation and deadline.

For the owning reactor, the sequence closes the lost-wakeup window:

\begin{enumerate}
    \item Capture the exact CQ list identity and compare its work generation
        with the reactor's last-seen generation; old ring occupancy is not readiness.
    \item Register a waiter against the CQ's generation counter.
    \item Recheck the captured generation after registration; readiness closes
        the lost-wakeup window without observing or discarding a result.
    \item Park with the original deadline. Unrelated wakes recheck and repark;
        completion cancels unused source/watchdog interests and revalidates queue
        identity before advancing the seen generation.
\end{enumerate}

This is the \textbf{single wait point} for the entire shard. Three event sources
converge on it:

\begin{itemize}
    \item Kernel completions (CQ entries from \texttt{submit} operations).
    \item Endpoint readiness (a coalesced wake when messages arrive on a bound
        endpoint).
    \item Device interrupts (a coalesced wake from a bound interrupt object).
\end{itemize}

The shard does not need separate wait operations for timers, IPC messages, and
device events. One aggregated wait covers all of them.

\section{LP affinity for CQ waits}

A thread that blocks in \texttt{checked CQ wait} is assigned an affinity LP. When woken,
the scheduler returns it to the same LP rather than scanning for the least-loaded
one. This has three benefits:

\begin{enumerate}
    \item Timer events stay on the same LP's queue, eliminating
        cross-LP migration races (observer-not-found when a completion is posted
        on a different LP than the one where the waiter was registered).
    \item Cache warmth is preserved: the waking thread finds its data
        in the LP's local caches.
    \item Shard-to-LP affinity is maintained: the Sitas shard that blocked
        on CQ 0 on LP 2 wakes up on LP 2, where its shard-local state lives.
\end{enumerate}

\section{Operation IDs versus per-operation capabilities}

An earlier experimental design returned a \texttt{CompletionCap} for every
submission. The final ABI uses \textbf{operation IDs} for the common path:

\begin{itemize}
    \item \texttt{submit()} returns an \rustfn{OperationId} (a lightweight
        identifier).
    \item The result arrives in the CQ with the same operation ID.
    \item No capability-table slot is consumed for common operations.
    \item A first-class operation capability is created only when independent
        waiting, cancellation, delegation, inspection, or policy requires it.
\end{itemize}

This avoids capability-table pressure for high-rate operations (timer events,
network packet completions) while preserving the capability model for operations
that need first-class authority.

Operation identities use one checked counter for the lifetime of a boot, shared
by capability-backed and detached submissions. It issues values from one through
\texttt{u64::MAX - 1}; zero and the syscall submission-failure sentinel
\texttt{u64::MAX} are excluded. Exhaustion permanently rejects new submissions
with the existing \texttt{WouldBlock}/submission-failure result before reserving
record, watch, timer or capability resources. Existing operations remain usable.
Failed preparation never refunds an identity, and namespace replacement never
resets the counter. Admission failure therefore does not promise retry progress.

\section{Completion-record admission}

Capability-backed and detached operations share a namespace's configured
submission-slot limit. A separate record budget counts retained state: at most
the smaller of that capacity and 1,024 records per namespace, and 8,192 per
node. Ordinary domains share 6,144 records; kernel-designated platform domains
may use the remaining pool. The service loader currently configures 16 slots.

A completion retains its charge while a kernel waiter or callback holds a
strong reference, even after capability closure or domain teardown. A detached
operation moves its charge into the CQ backlog until its result reaches the
ring or is discarded during teardown. A fresh generation receives a fresh
budget owner; old releases cannot credit a replacement. Closing a captured
object also verifies its identity under the registry lock before revocation.

Observer entries have separate admission, but general weak-only Arc/control-block
allocations and the entire kernel heap still require broader accounting.
Timer events have their own charges because deferred
cancellation can outlive the operation record.

Timer cancellation borrows the handle's retained state allocation and removes
only a queue entry with that exact object identity. No private numeric
cancellation counter remains. Retained strong ownership prevents address reuse
during lookup; equal LP, deadline or cancellation flags grant no authority over
a successor. Weak-only backing remains charged to its original sponsor.
This adds no admission failure and is separate from public operation IDs.

Backlog-to-ring publication retains delivered detached-record charges in a
fixed two-class owning batch until the completion registry is unlocked.
Ordinary/platform charges retain their original accounts; no disposal storage
is allocated. Full FIFO flushing and logical slot updates remain serialized.
The same admitted detached nodes relink into the shared retirement list and
free after local unlock, before either accounting class refunds.
Checked batch refunds finish before CQ parking or producer notification;
failed ring writes retain the complete backlog entry. Registry-map metadata
and broader outer-context qualification remain separate work.

Detached-record metadata uses the shared admitted map: fallible node storage is
prepared outside the completion registry, then relinked after exact namespace
and CQ validation. Terminal removal transfers its owning node to the direct
receipt or backlog. Explicit namespace close drains all remaining nodes after
local unlock. Namespace, detached-preparation and terminal-receipt abandonment
retain their complete fields, accounts and sources; ordinary rejection uses an
explicit unstarted finish. Capability/CQ/global map metadata and wider caller
contexts remain open. None of these owners is a physical completion receipt or
permission to replay accepted work.

Capability-backed completion submission prepares records, waiter lists, optional
watch admission and shared authority storage outside the completion registry.
Hidden authority admission and final joint publication each revalidate the exact
namespace and original accounts under serialization. Timer node and producer
preparation also leave that guard. Ordinary rejection retains the complete owner
until explicit post-guard disposal; abandonment retains every field.
Capability timers capture one absolute deadline before preparation and preserve
it through publication and enqueue. Namespace teardown can cancel a prepared
node before insertion, retaining its event charge until actual disposal.
Registry-map allocation, close and outer contexts remain separate work.

\section{Completion-queue admission}

Queue preparation reserves a registration count and kernel-owned backing
bytes. Each namespace may register 32 queues with at most 256\,KiB of backing;
node limits are 2,048 queues and 4\,MiB. Ordinary domains share 1,536 queues
and 3\,MiB, leaving a reserve for kernel-designated platform domains.
Backlogs are preallocated from the namespace's submission capacity, clamped
to 1,024 and rounded with checked arithmetic. Heap rings use aligned
4\,KiB backing. Physical rings remain owned by their address-space mappings;
their pages are outside this heap-byte budget.

Preparation is fallible and precedes publication. Replacement must admit
both old and staged backing; failure preserves the original queue and its
pending results. Physical-ring initialization follows admission and allocation,
and a frame already registered to another queue is rejected. Reusing the same
queue's frame requires a quiescent consumer. Successful replacement discards
undelivered results rather than migrating them.

An owning loader guard tears down the partially mapped domain if a CQ cannot
be prepared, including any queues already installed. Trusted ambient supervisor
paths designate platform domains before preparation; scoped and syscall
preparation use ordinary admission. General page allocation, observer storage
and kernel metadata still require further admission and fallible cleanup.

\section{Owning endpoint-close and thread-exit registrations}

An endpoint-close watch owns a one-shot callback and a removable registration.
Dropping its completion cancels locally without closing the source endpoint or
waiting for endpoint death. Message arrival remains a readiness event and does
not complete a lifecycle watch.

Each endpoint accepts at most 128 close registrations across callers. The
submitting completion namespace may retain its configured capacity, clamped to
1,024 entries; node admission is 8,192 with an ordinary share of 6,144. Entries
are individually allocated fallibly, with no retained vector capacity, and
keep their original generation's charge until actually released. Registration
failure rolls back the unpublished completion through one owning guard.

Endpoint close detaches notifications without allocation. Callbacks run after
the IPC and list locks are released; token destruction enters only the
independent list lock. A detached entry retains its charge even if its token
is cancelled before notification. Late callbacks cannot change a cancelled
terminal result or complete a replacement with the same numeric capability.
List destruction is iterative to bound kernel-stack use.

External thread-exit watches share the namespace and node registration pools
with endpoint-close watches. Each target thread accepts at most 128 entries.
Cancelling such a watch removes only the subscription; the target remains
alive. Lookup, generation checking and insertion are serialized with thread
retirement. An absent or stale target completes immediately, while admission
failure rolls back the unpublished completion and reports failure rather than
pretending that the thread exited. Reaping invokes callbacks outside observer
and master-table locks, before releasing the thread's stack.

Worker-backed completions bind their callback and registration to the fresh
thread before publication and execution. Cancellation remains pending until
that worker actually exits; this preserves producer lifetime instead of treating
work as a removable observation. Terminal completion and namespace teardown
release the registration. Installing a late observer is fenced against exact
completion-object replacement, including when a kernel owner retains the old
object. Kernel thread construction and general control-block allocation still
need broader admission and fallible cleanup.

\subsection{Kernel completion callbacks}

Non-scheduler completion callbacks return an owning registration token and share
the event-watch account, with at most 128 entries per completion. Cancelling the
token removes only the subscription: it neither terminates the producer nor
releases the operation's buffer. Asynchronous callers holding an existing
completion reference use exact-object registration to reject a replacement with
the same numeric address-space and capability identifiers.

Terminal checking and insertion share the operation's state lock. A callback
registered after completion or result consumption is invoked immediately,
outside registry/source guards and without retaining an entry. Otherwise,
notification follows CQ publication. Entries remain charged while detached and
are released before their callbacks run. Teardown and unpublished-record rollback
discard entries even when an old completion or token remains retained.
Lists allocate fallibly on first subscription. Empty control blocks and arbitrary
callback capture sizes remain outside these entry counters.

Event and worker subscriptions detached by terminal completion stay in one
transition owner through terminal-state and CQ-result publication. Disposal
follows both local registry and state unlock, before notification. The exact CQ
source is captured at publication: a reentrant destructor replacing the queue
cannot redirect the old wake to its successor. Installation returns replaced or
rejected subscriptions for disposal after both guards. Cancellation rejects a
late event watch but retains the worker-exit subscription; terminal installation
retains neither. Timer cancellation, record/authority/map metadata and outer
producer/IRQ contexts remain separate qualification work. These subscription
transitions grant no physical cleanup proof or permission to replay accepted work.

CQ source-list, backlog and heap-ring admission/allocation run outside the
completion registry, including partial-error disposal. Preparation retains the
exact namespace root, CQ account, submission capacity and trusted classification;
publication rechecks identity and retirement. Physical frames remain untouched
until alias checks and initialization under the same registry hold as queue
publication. Rejection retains prepared backing and original charges until
unlock. Whole-namespace preparation includes its private CQ map node. Fresh
live registry-map nodes, unified authority, record construction, timers and outer
caller/IRQ contexts remain separate. A captured identity supplies no physical
pin or permission to retry accepted work; frame owners must quiesce consumers.

Detached terminal publication returns the complete remaining timer-bearing
record beyond registry unlock before destroying its observer/cancellation
fields. Direct-ring delivery leaves the original record charge with that owner;
only actual backlog retention transfers it into the retained entry. Notification
then uses the exact published CQ source, even if the queue was replaced during
the intervening phase. A firing timer still owns its event/node and producer
reference during notification, retaining separate event admission until queue
processing finishes. Map removal, backlog draining, construction and outer
queue/IRQ contexts remain separate. This is logical terminal disposal, not a
physical cleanup receipt or a retry owner.

Detached plain/timer submissions capture exact namespace root, record/event
accounts, trusted classification, capacity and CQ source before preparation.
Record/event admission and timer node/observer allocation run outside the
completion registry. Borrowed publication rechecks that capture and retirement;
a replaced queue rejects even if its numeric ID still exists. Rejected owners
retain their fields through unlock for unstarted rollback, with no public retry
owner. Accepted nodes enqueue exactly once afterward; teardown in between flags
the retained event and keeps its charge until cancelled insertion is discarded.
Map/authority metadata, backlog reconciliation, capability-backed construction
and outer caller/IRQ contexts remain separate. Captured identity is no physical
pin or cleanup receipt.

\section{Owned completion and CQ waiters}

Completion and CQ scheduler waiters use fallible registration before a thread
is removed from its Ready queue or published as Blocked. Rejection preserves
its state, queue membership and migration constraints; an already-ready source
does not park it. Each source links at most 64 registrations, each waiting domain
generation 1,024, and the node 8,192 with an ordinary share of 6,144. The waiting
domain sponsors the entry independently of the source's owner. These are kernel
policy limits, separate from records, close watches, timers and CQ backing.

The Waker owns the registration. Ready admission cancels it even if a competing
watchdog wins and another strong Waker survives; reaping a Blocked thread also
cancels it. Detached notification storage remains charged until actually freed.
Token destruction enters only the independent list lock. Notifications run
after source locks are released, and CQ notification lists can be drained and
rearmed without growing an unbounded observer queue. Retirement closes the
generation's sponsor, while late cleanup cannot credit a replacement ASID.

A timed completion wait reports \texttt{WAIT\_ADMISSION\_FAILED} when parking
is rejected, retaining the operation and its Rust owner for retry or safe Drop.
The untimed completion-wait ABI instead yields cooperatively and retries until
terminal completion, preserving borrowed-buffer safety. This overload fallback
does not guarantee efficient idle waiting or producer progress. CQ waits retain
their existing return shape and can return without parking when admission fails.

Timed waits mask local interrupts across Blocked publication, watchdog enqueue
and the condition recheck. Without that interval, a quantum interrupt could
switch out the waiter before its deadline wake exists. An owning local mask
restores the entry interrupt state on rejection and is dropped before yielding;
it holds no lock across a context switch. Watchdog storage still needs admission.

Endpoint-readiness and pending-call waiters share these admission pools and
owning cancellation, as described in \autoref{chap:endpoints}. Untimed IPC waits
also retry under pressure rather than returning while a server still holds a
live loan. IPC source callbacks run after its registry is released.

Kernel scheduler-blocking mutex and read/write-lock waiters also share these
budgets. Each mutex source and each reader/writer source links at most 64 entries.
Uncontended acquisition allocates nothing; first contention prepares the list
fallibly. Rejected admission leaves the thread runnable to yield and retry.
Local interrupt masking spans park and the lost-wake recheck, then ends before
yield; an unlock preceding list insertion must not strand a preempted caller.
Unlock releases ownership and detaches all candidates before callbacks; the
final reader releases an RwLock's writer waiters. Notifications do not reserve
ownership, and broadcast does not guarantee fairness or writer priority.
The blocking family currently has kernel test users, not production callers;
existing registry/allocator spin locks are unchanged.

Scheduler timer observers also use owning admission. Non-scheduler producers
install one callback in an embedded slot rather than an unbounded weak queue.
Rejected sleep admission leaves the caller runnable to yield until its counter
deadline, preserving the requested interval without queuing an event.
Sleep/watchdog events have separate generation-owned admission: 1,024 per
generation, sharing the 8,192-event node pool and its 6,144 ordinary share with
completion timers. These are independent domain accounts, not one combined
domain allowance. Cancellation state, watchdog callback and fixed-size queue
node preparation precede parking. Queue insertion allocates nothing; anonymous
nodes form a sorted owning list with iterative reclamation. The quantum/idle-wake
event has one inline queue slot per LP, outside anonymous admission. Rejection
therefore cannot consume scheduler preemption storage. Charges remain until the
actual event is removed, including an aborted sleeper awaiting its deadline.

Every scheduler Observable source now requires fallible owning registration;
there is no weak-only default. Steady-state publication and self-test results
use the same bounded waiter source, with notification outside source guards and
no stale-entry pruning after timeout. Non-scheduler completion callbacks have
separate event-watch sponsorship. General weak-only/control-block backing and kernel
heap accounting remain incomplete. CQ replacement still requires a quiescent
consumer; discarding registrations is not live reactor migration. Silently
rejecting an old void registration would lose a blocked thread's wake source.

\section{Cancellation and buffer ownership}

When a userspace task drops a completion handle or explicitly cancels an
in-flight operation:

\begin{enumerate}
    \item The kernel marks the operation as \texttt{Cancelling} but \textbf{retains
        any transferred buffer.} The buffer may still be the target of DMA or
        kernel access.
    \item A terminal \texttt{Cancelled} completion is eventually posted to the CQ,
        returning buffer ownership to userspace.
    \item On domain teardown (process exit), outstanding buffers may be leaked
        rather than freed while the kernel or a device may still touch them.
        Reclamation goes through explicit operation and device teardown.
\end{enumerate}

Under this contract, a buffer is retained while the kernel or device may still
reach it. The safe Rust wrapper consumes the owned value on submission and returns
it on terminal completion.

\section{Reliability and latency consequences}

\begin{enumerate}
    \item Non-lossy completions are a correctness requirement: a disk-write
        confirmation, a timer expiry, or a sensor reading is a fact and losing it
        is a bug. The backlog retains terminal results when the ring is full.

    \item The single aggregated wait eliminates a class of race conditions:
        a shard that must wait on ``timer or IPC message or device interrupt'' in
        a conventional OS must manage three separate wait objects, with potential
        lost-wake races between checking one and arming another. One CQ means one
        atomic check-and-arm sequence.

    \item Per-shard CQ rings enable predictable latency: no shard wakes
        another shard's executor to deliver a completion. Wakes are targeted,
        bounded, and proportional to the actual work.

    \item The CQ ring is zero-syscall in the common case: draining entries,
        processing results, and continuing the loop require no kernel
        transitions. A syscall occurs only when the ring is empty and the shard
        must block.

    \item Cancellation is defined, not best-effort: every cancellation
        path ends in a terminal completion. There is no ``the buffer might or
        might not be freed'' ambiguity. The ownership contract is explicit and
        testable.
\end{enumerate}
