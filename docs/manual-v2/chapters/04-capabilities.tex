\chapter{Capabilities: Authority Without Ambiguity}
\label{chap:capabilities}

A capability is the answer to one question: \textbf{``May I perform this
operation?''} It grants permission to act. Operations describe the work.
CharlotteOS capabilities are unforgeable, delegable, and attenuable.

\section{What a capability is}

A capability is a per-address-space handle that names a kernel object and carries
a rights mask. The kernel maintains a \textbf{capability table} for each protection
domain. An entry in this table is the only way a userspace process can reference a
kernel object.

Capabilities have four key properties:

\begin{itemize}
    \item Unforgeable: a process cannot create a capability through
        computation. The kernel must issue it through an authorized creation,
        bootstrap, or delegation operation.
    \item Scoped: a capability is valid only in the domain that holds it.
        Capability index 3 in domain A refers to a different object (or nothing)
        than capability index 3 in domain B.
    \item Righted: a capability carries a rights mask specifying which
        operations are permitted. A client connection might carry only
        \texttt{SEND | CALL} rights without connection-minting authority.
    \item Revocable: when a kernel object is destroyed, all capabilities
        referencing it become invalid. Subsequent use returns an error.
\end{itemize}

\section{Object types and their rights}

The unified namespace records six authority families. Their payload registries
distinguish subtypes and enforce the relevant rights or ownership checks. The
table gives current operations; only the named IPC and memory masks are rights
bits. A CQ identifier is a domain-local queue selector, rather than a separate
capability kind, and timers produce completion capabilities.

\section{Delegation and attenuation}

Capabilities can be \textbf{delegated} to another protection domain through IPC.
When delegating, the sender may \textbf{attenuate} the rights: the receiver gets a
subset of the rights the sender held. A service manager that holds a connection
with \texttt{SEND | CALL | MINT\_CONNECTION} rights can delegate a client-facing
connection with only \texttt{SEND | CALL}, keeping minting authority for itself.

Delegation happens in the kernel, mediated by the IPC path. The sender specifies
the target domain, the capability to delegate, and the reduced rights mask. The
kernel validates that the sender actually holds the capability with at least the
rights being transferred.

\section{Generation-safe lookup}

Capability values are opaque serials consumed monotonically within one namespace.
Closing an entry does not make its serial available again; exhaustion rejects
creation instead of wrapping. Lookup checks the owning namespace and object
family. A removed serial therefore cannot name a later object in that namespace.

Address-space slots have a separate generation. A replacement namespace can reuse
numeric values, so pending kernel owners capture the original namespace identity
and root generation. A scalar ASID or handle alone cannot authorize delayed
cleanup. These rules are implemented in \repofile|crates/catten/src/capability.rs|
and its \repofiletext|crates/catten/src/capability/record.rs|{record preparation}.

\section{Bootstrap: how capabilities enter a domain}

A newly created protection domain starts with an empty capability table. It
receives its initial capabilities through the \textbf{config-page contract}: a
mapped page that the supervisor populates with typed entries before the domain
begins execution. The records depend on the launch policy:

\begin{itemize}
    \item Ordinary deployed applications borrow a grant-controller connection
        and their immutable signed deployment descriptor through \texttt{Context}.
    \item Trusted platform services may receive a name-service connection.
    \item Drivers receive the selected MMIO, interrupt and DMA grants.
    \item Services normally create and own their listening endpoint.
\end{itemize}

The launch header separately describes the default CQ mapping. Launch-owned
connections are borrowed through \texttt{Context}; applications must not adopt
them as new owners. \autoref{sec:reconnecting-client} shows a complete client.

After bootstrap, additional capabilities arrive through IPC: the name service
delegates service connections; the supervisor delegates device grants; other
services delegate whatever the protocol authorizes.

\section{Authority and audit consequences}

\begin{enumerate}
    \item A process starts without ambient authority. Every capability it
        holds was explicitly granted by
        a trusted component (the supervisor, the name service, or another service
        under a protocol). There is no ambient authority to strip away and the
        default is none.

    \item Kernel-mediated authority is enumerable: a process's capability table
        records the kernel objects it may use. This makes authority easier to
        audit, but does not by itself account for device side effects, protocol
        state, or implementation defects.

    \item Delegation is mediated: a process cannot grant authority it
        does not hold; it cannot grant rights beyond what it possesses; and every
        delegation crosses the kernel, which enforces both constraints.

    \item Teardown revokes the destroyed domain's capabilities and closes its
        endpoint relationships. Existing tests cover stale connections and
        pending-call reconciliation.

    \item Completion submissions share a bounded per-domain operation budget;
        a full budget returns \texttt{WouldBlock}. Completion timers also have
        separate event limits: at most the domain's completion capacity,
        clamped to 1,024, and 8,192 events across the node. Ordinary domains may
        use 6,144 of those events, leaving a share for kernel-designated
        platform work. A cancelled event stays charged until its LP removes
        the queue node. Shared capability-record admission additionally covers
        all six families: 4,096 records per namespace, 65,536 per node and
        49,152 for ordinary domains. These bounds do not account for every
        kernel allocation or aggregate principal usage.
\end{enumerate}

Timer cancellation produces a terminal cancelled result without waiting for
the original deadline. The completion record owns cancellation, while the
event owns its admission charge. Teardown can therefore release the record
without falsely reclaiming a still-queued event's capacity. Timer callbacks
verify the exact original completion object under the registry lock before
publishing a result; a delayed callback cannot complete a replacement merely
because it reused the same ASID and numeric handle.
