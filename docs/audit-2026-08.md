# CharlotteOS Code/Documentation Cross-Check Audit — August 2026

This document records a cross-cutting audit of the codebase against the
architectural documentation in `docs/` (Markdown design notes and the
`manual-v2` LaTeX manual) plus the two prior audit reports
(`functionality-and-logic-audit-2026-07.md`, `distributed-systems-audit-2026-08.md`).
It supersedes neither the source nor the manual; those remain authoritative
where they agree with the implementation.

Seven subsystem investigations covered: scheduler + completion queues;
IPC/capabilities/memory objects/EL0 loader; networking; persistent storage;
Raft/authorization/artifacts/live upgrade; AArch64 bring-up + device drivers +
SMMU; and the Sitas shard runtime.

---

## 1. Executive summary

The codebase is well-structured and unusually honest about its own state: the
manual and `implementation-status.tex` separate "implemented" from "intended",
and the majority of high-level claims verified cleanly against code (GICv3 +
generic timer + ECAM + SMP bring-up, ASID isolation with the HVF caveat,
capability/endpoint IPC model, smoltcp checksum handling, NVMe DMA/IOVA
lifetime, object-store v3, Raft safety, artifact signing).

Three recurring patterns account for most findings:

1. **Syscall-boundary hardening gaps** — several `panic!`/`expect` on
   userspace-controlled inputs, plus unbounded capability/memory allocation,
   contradicting the documented "`WouldBlock` is non-fatal" and "bounded"
   contracts.
2. **Documentation drift** — status documents overstate "Verified" coverage in
   a few places, while other documents lag the code.
3. **Intentional deferrals recorded as open debt** — e.g. unauthenticated DNS
   mutation endpoints, per-domain resource quotas, and the SMMU/ITS paths are
   mostly *acknowledged* limitations rather than undocumented gaps.

The highest-severity items from the initial pass (syscall panics, the
`ipc_recv_vec` register mismatch, signature verification missing from the Sitas
loader, owner-only physical-address disclosure) were fixed in this session; see
§4.

## 2. Verified claims (spot-checked against code)

These are the claims that, after review, match the implementation:

- **AArch64 bring-up:** GICv3 + EL1 *virtual* timer (`CNTV_*`, PPI 27), PCIe
  ECAM enumeration, atomic SMP secondary-CPU startup
  (`cpu/multiprocessor/startup.rs`, `cpu/isa/aarch64/interrupts/gic/mod.rs`).
- **ASID TLB isolation + HVF caveat:** per-LP `CURRENT_LOGICAL_ASID`, whole-TLB
  flush under `hvf_compat`, SVC caller attribution from the tracked logical
  ASID rather than `ttbr0_el1` read-back.
- **Endpoint IPC model:** scalar send/call/receive/reply, connection delegation
  with rights attenuation, reply tokens, memory-object move/lend/copy with
  reply-bound revocation.
- **Typed `SyscallNumber` enum:** caller identity derived from trap/thread
  context, never a userspace parameter.
- **ELF loader:** CLS2 Ed25519 signature verified before mapping (general
  loader path); fixed-address, segment-aware loading.
- **Networking:** frouter EtherType routing (`0x0800`/`0x0806` → tcpip,
  `0x88b5`/`0x88b6` → relmsg/disco, `0x88b7` → raft); smoltcp 0.13 computes
  TX checksums and verifies RX checksums in software (correct for a NIC with no
  offload); 64 KiB reliable-message fragmentation/reassembly.
- **Storage:** NVMe DMA/MSI-X driver with correct PRP-list + data IOVA lifetime
  (released exactly once on completion or submission failure); object-store v3
  (mirrored generation-selected directories, device-scaled capacity, ≤16
  extents, integrity hashes, allocation reconstruction, copy-on-write).
- **Raft:** transport-independent core with two-node election, persistent
  single-voter restart, discovery-led join; host tests pass (see §3 C1).
- **Artifact signing:** CLS2 Ed25519 `.note.charlotte-sig` binding bytes to
  name/class/release-rollback/parallel-permission/provenance, enforced by the
  loader and the deploy path.

## 3. Findings

Severity legend: **H** = high (security / cross-domain DoS), **M** = medium
(correctness), **L** = low / documentation.

### 3.1 Syscall boundary (H/M)

- **H — kernel panic from unvalidated EL0 syscall inputs** (`crates/catten/src/syscall/mod.rs`).
  Prior to this session, several syscall paths panicked on caller-controlled
  values, letting any EL0 service crash the node:
  - `sys_completion_submit` panicked on an unknown `op_code` (arbitrary
    `regs[1]`), on a missing address space, on an untranslatable user VA, and
    on any `submit` error (full completion table).
  - `sys_completion_poll` panicked on an unknown capability.
  - `sys_completion_wait_timeout` panicked (`expect`) on an unknown capability.
  **Fixed** in this session (§4.1), including checked EL0-writable translation
  of every byte touched by the completion Read smoke path; unaligned and
  cross-page buffers no longer create an unchecked physical write.
- **H — no per-domain resource quotas** (`crates/catten/src/memory/object.rs`,
  `crates/catten/src/ipc/mod.rs`, `crates/catten/src/syscall/mod.rs`). Memory
  objects, IPC endpoints, and mailbox caps are unbounded `BTreeMap`s; only the
  completion table (16) is bounded. A domain can exhaust kernel heap and
  physical frames, contradicting the "bounded capability table" claim in
  `04-capabilities.tex`. **Partially fixed** in this session via a per-allocation
  page cap (`MAX_MEMORY_OBJECT_PAGES`, 64 MiB); full per-domain *total* quotas
  remain future work and should be tracked alongside the existing "resource
  accounting" limitation in `implementation-status.tex`.
- **M — `ipc_recv_vec` result-page register mismatch** (`crates/catten-syscall/src/lib.rs:1319-1355`
  vs `crates/catten/src/syscall/mod.rs:1256-1259`). The wrapper passed
  `result_page` in x2 while the kernel read x3, silently disabling vector-receive
  result delivery. **Fixed** in this session (§4.2), together with the wrapper's
  compiler memory contract and transactional BorrowWrite validation.

### 3.2 Memory safety / unsafe code (H/M)

- **H — `unsafe impl Send/Sync` with a misleading justification and raw ring
  pointers escaping the lock** (`crates/catten/src/completion/mod.rs`). The
  justification comment claimed the ring buffer was "behind a `Box`" when the
  field is `Option<Vec<u8>>`, and `cq_ring_of` hands `*mut CompletionQueueRing`
  to callers (self-tests) that dereference it outside the `COMPLETIONS` lock,
  creating a use-after-free hazard if the AS is closed concurrently.
  **Fixed** this session (§4.3): the justification now covers both heap-backed
  and physical-frame-backed rings, and `cq_ring_of` is an `unsafe fn` whose
  lifetime/quiescence obligation is explicit at every self-test call site.
- **M — raw physical-address disclosure** (`crates/catten/src/memory/object.rs:get_phys`).
  Any capability holder — including a read-only borrower — could read raw
  physical addresses, contradicting the manual's IOVA-only DMA boundary.
  **Fixed** this session: `get_phys`/`get_phys_page` are now owner-only (§4.4).
  Vector-receive result delivery no longer uses raw physical disclosure and
  accepts a rights-checked BorrowWrite object through `write_bytes`.

### 3.3 Scheduler / completion queues (M)

- **M — first quantum after an idle→busy transition can be 50 ms instead of
  10 ms** (`crates/catten/src/cpu/scheduler/lp_schedulers/round_robin.rs:162-186`).
  The idle-wake timer and the round-robin quantum reuse `TimerEventKey::SchedulerQuantum`,
  and `ensure_event` preserves an existing keyed deadline, so a freshly-woken LP
  skips its first preemption. Genuine latency bug, not yet fixed.
- **M — `submit_worker` can strand a completion** (`crates/catten/src/completion/mod.rs:661-684`).
  Exit-observer registration failure is discarded; a fast-exiting worker leaves
  its capability permanently `InFlight`. Not yet fixed.
- **M — IPI coalescing documented but not implemented**
  (`crates/catten/src/cpu/scheduler/system_scheduler/mod.rs:187-273`). Every
  cross-LP admission (including idempotent no-op wakes) sends an unconditional
  unicast IPI; only enqueue-side idempotency exists. The `implementation-status`
  "coalesced remote shard wakes — Verified" claim overstates the mechanism.
- **L — `min_complete` ignored** by `wait_on_cq`/`wait_on_cq_timeout`
  (`crates/catten/src/completion/mod.rs:1154,1273`), despite the state-machine
  doc describing entry-count semantics.

### 3.4 AArch64 / device / SMMU (M/L)

- **M — GIC active-priority registers cleared incompletely** (`crates/catten/src/cpu/isa/aarch64/interrupts/gic/mod.rs:241-242`).
  Only `ICC_AP0R0_EL1`/`ICC_AP1R0_EL1` are zeroed; the stale NVMe LPI at
  effective priority ~0x90 lives in `ICC_AP1R2_EL1` and is not cleared, so the
  fix documented in `sbsa-ref-bringup.md` does not do what it claims.
- **M — SMMU command/event-queue indexing is non-architectural** (`crates/catten/src/device/smmu.rs:343-364,627-670`).
  PROD/CONS are written as raw indices rather than `index << 5`; works against
  QEMU but not real SMMUv3. The CD ASID is also placed in the TCR word rather
  than the TTB0 field (`smmu.rs:211-227`).
- **M — IORT `stream_id()` off-by-one** (`crates/catten/src/environment/acpi/sdt/iort.rs:44`):
  `offset > id_count` accepts `offset == id_count`, mapping one requester-ID past
  the valid range.
- **M — MADT entry iterator off-by-one** (`crates/catten/src/environment/acpi/sdt/madt/mod.rs:50-61`):
  skips the first entry and returns the past-end entry (x86_64 path only).
- **M — FEAT_NMI reads `ID_AA64PFR1_EL1` instead of `ID_AA64PFR0_EL1`**
  (`crates/catten/src/cpu/isa/aarch64/system_info/isa_extensions.rs:73-88`).
- **M — `allocate_contiguous` can loop/read out of bounds**
  (`crates/catten/src/memory/physical/mod.rs:157-171`): no upper bound or
  exhaustion check on the alignment scan.
- **L — ITS routes every LPI/MSI to processor 0** (`crates/catten/src/cpu/isa/aarch64/interrupts/gic/its.rs:94`),
  defeating MSI affinity.

### 3.5 Storage (M/L)

- **M — 32-bit truncations**: NVMe device size (`nsze as u32`,
  `crates/catten-services/src/bin/nvme.rs:738`) and directory generation
  (`u32`, `crates/catten-services/src/bin/objstore.rs:375`) wrap after 2^32,
  breaking geometry/generation-selection.
- **M — `make-nvme-image.py` directory-slot collision** (`scripts/make-nvme-image.py:213-218`):
  slot derived from only 8 bits of the FNV hash, so distinct artifacts colliding
  in those bits silently overwrite a directory entry.
- **L — block `OP_WRITE` documented as "Move" but implemented as "BorrowRead"**
  (`docs/manual-v2/chapters/17-storage.tex:73-75,119` vs `crates/catten-services/src/bin/nvme.rs:910-959`).
- **L — `charlotte-protocol-objstore` crate docstring is a version behind**
  ("v2", "512-entry directory", "one extent" vs v3, device-scaled, ≤16 extents).

### 3.6 Networking (M/L)

- **M — `relmsg` trusts caller-supplied length without checking object size**
  (`crates/catten-services/src/bin/relmsg.rs:534-571`): a 4 KiB moved object with
  a 65535-byte length causes a 64 KiB out-of-bounds read.
- **M — `tcpip`/`httpd` dereference a possibly-invalid mapping**
  (`crates/catten-services/src/bin/tcpip.rs:354,484`; `httpd.rs:64,242,470-483`):
  `memory_map_any` status is discarded, and httpd reads some entries from a
  hardcoded scratch address instead of the returned mapping.
- **L — `dns` `OP_CATALOG` count field overstates the number of emitted entries**
  (`crates/catten-services/src/bin/dns.rs:1958-1965`) for catalogs > ~4 KB.
- **L — per-peer Raft outbound queue unbounded + `Vec::remove(0)`**
  (`crates/catten-services/src/relmsg_transport.rs:246-311`).

### 3.7 Consensus / authorization / deployment (H/M)

- **H — unauthenticated DNS mutation endpoints** (`crates/catten-services/src/bin/dns.rs`).
  `OP_DEPLOY`/`OP_REGISTER`/`OP_UNREGISTER` accept any caller holding a
  connection, allowing a client to overwrite the replicated deployment manifest
  or hijack a name. This is *acknowledged* (`cluster-artifact-and-placement-model.md`,
  `19-cluster-vision.tex`) and deferred pending a separately delegated
  administrator capability — open security debt, **not fixed** this session.
- **M — deployment/key/catalog reads bypass the Graft read barrier**
  (`crates/catten-services/src/bin/dns.rs:1799-1822,1855-1864,1934-2002`): answered
  from locally applied state with no read barrier or leader forwarding. The
  earlier F8 finding was closed only for `OP_LOOKUP`/`OP_CALL`.
- **M — Raft no-op sentinel is `data.is_empty()`** (`crates/catten-graft/src/types.rs:69-71`),
  so an empty client command is silently dropped.
- **M — deploy agent hard-codes the `greet` name** (`crates/catten-services/src/bin/agent.rs:196-205`);
  the "agent verifies the assigned artifact" claim is greet-specific.
- **L — live-upgrade design doc describes a dead code path**: the
  endpoint-takeover + multi-state rollback helper (`supervisor::spawn_upgrade`)
  is never called; the real path (`sys_spawn_upgrade`) is single-state, no
  endpoint delegation. The manual (`18-live-upgrade.tex`) is correct; the design
  doc (`charlotte-live-upgrade-design.md`) is not.

### 3.8 Sitas shard runtime (M)

- **M — the sitas boot test did not signature-verify its ELF**: `el0_sitas.rs`
  used an inline loader that skipped `verify_elf`, diverging from the general
  loader. **Fixed** this session (§4.5).
- **M — `el0_sitas` config page never zeroed** (`crates/catten/src/self_test/el0_sitas.rs:309-322`):
  `shard_cq_layout()` can read garbage from a reused frame, nondeterministically
  selecting an unmapped per-shard ring. (Masked on cold boot by zeroed frames.)
- **L — per-shard CQ rings are implemented in the general loader but not
  exercised by the sitas test**, which uses its own inline loader and only maps
  queue 0. The "boot-validated per-shard CQ" claim is overstated.
- **L — budgeted polling never yields** (`sitas-core/src/shard_executor.rs:233-262`):
  the budget is a fairness yield point, not a scheduling boundary, contradicting
  the manual's starvation-prevention claim.

## 4. Fixes applied in this session

These changes were verified by the host-test suite, AArch64 and x86-64 kernel
build/check paths, AArch64 `clippy -D warnings`, signed service-bundle
reproduction, and an ordinary four-LP AArch64 QEMU boot. The authoritative boot
verdict was `SELFTEST COMPLETE: passed=18 failed=0 pending=0`; the synchronous
suite exercised the new completion-buffer and vector-receive regressions before
that verdict.

1. **Syscall panic elimination** (`crates/catten/src/syscall/mod.rs`):
   `sys_completion_submit`, `sys_completion_poll`, and `sys_completion_wait_timeout`
   now return caller-visible errors instead of panicking on caller-controlled
   inputs (`op_code`, user VA, unknown capability, full completion table).
   Completion Read uses a permission-aware page-table translation for all four
   destination bytes, validates the complete range before writing, supports
   unaligned/cross-page buffers, and rolls back its reserved completion slot on
   validation failure.
2. **`ipc_recv_vec` register fix** (`crates/catten-syscall/src/lib.rs`): the
   wrapper now places `result_page` in x3, matching the kernel's read, and
   captures `arg0`/`reply` from x2/x3 respectively. Its inline assembly no
   longer claims `nomem`, so the compiler observes the result-page write.
   The kernel validates and fills owned or BorrowWrite result objects before
   dequeuing, leaving the message queued on invalid/read-only/undersized input.
3. **Per-allocation memory cap** (`crates/catten/src/memory/object.rs`): added
   `MAX_MEMORY_OBJECT_PAGES = 16_384` (64 MiB), rejecting oversized single
   `memory_alloc` requests. Full per-domain *total* quotas remain future work.
4. **Owner-only physical-address disclosure** (`crates/catten/src/memory/object.rs`):
   `get_phys`/`get_phys_page` now require the caller to be the object owner,
   closing raw-PA disclosure to borrowed-capability holders; DMA drivers should
   use the IOVA/`pin_for_dma` path.
5. **Sitas loader signature verification** (`crates/catten/src/self_test/el0_sitas.rs`):
   `load_user_elf` now verifies the CLS2 Ed25519 note before mapping, matching
   the general service loader.
6. **CQ raw-pointer contract corrected** (`crates/catten/src/completion/mod.rs`):
   the `Send`/`Sync` justification now covers heap-backed and physical rings,
   kernel producer serialization, and the shared EL0 consumer protocol.
   `cq_ring_of` is unsafe and documents the close/replace and single-consumer
   obligations at the API boundary.
7. **Completion ABI errors made explicit** (`crates/catten-syscall/src/lib.rs`,
   `crates/catten/src/syscall/mod.rs`): shared constants now define ready,
   pending/timeout, invalid-capability, and submission-failure results. Poll and
   timeout-wait distinguish invalid capabilities, and all wrappers document the
   sentinel/status values.
8. **Regression coverage added**: kernel self-tests cover invalid completion
   inputs, unaligned cross-page writes, read-only rejection and slot rollback,
   the memory allocation ceiling, non-consuming vector-result rejection, and
   successful vector receive into a BorrowWrite page.

## 6. Remaining high-priority work

1. **Full per-domain resource quotas** (memory objects, endpoints, mailbox/connection
   caps) — currently only a per-allocation page cap exists.
2. **Authenticate DNS mutation endpoints** — requires the delegated administrator
   capability described in `README.md` and `19-cluster-vision.tex`.
3. **Scheduler**: 50 ms first-quantum bug; IPI coalescing; `submit_worker`
   completion stranding.
4. **SMMU/GIC**: non-architectural queue indexing; incomplete active-priority
   clearing; IORT/MADT off-by-ones.
5. **Networking**: `relmsg`/`tcpip`/`httpd` length/mapping validation.
